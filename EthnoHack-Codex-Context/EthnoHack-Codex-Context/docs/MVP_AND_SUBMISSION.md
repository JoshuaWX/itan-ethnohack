## Organizer repository guide

The guide specifies the repository naming format `makeathon-2026-[team-name]-[challenge-name]`, recommends a public repository, README and suitable .gitignore, and asks teams to add collaborators with appropriate access. Its mandatory README covers the challenge and problem, technologies, installation and running, API-key setup where applicable, and screenshots, a demo or video link. Never commit credentials or .env files; document how to obtain and configure keys. Use clear commits, development branches and external links for large files. Verify the project runs from its instructions and check for exposed secrets before submission. Confirm any conflicting or updated instructions with organizers.

## Organizer demo guide

The presentation demo should show how the solution works, key features and optionally a use case in 2–3 minutes. The guide recommends 1280×720, MP4/MOV/WEBM and ideally under 100 MB, a clean screen and no distracting notifications. Audio is optional because the team can explain live. Suggested recording tools: OBS Studio, Microsoft Clipchamp, QuickTime Player, Free Screen Recording, Loom and ScreenPal; HandBrake or VEED.io can compress larger files. Upload alongside the presentation to the platform specified by organizers; contact their IT team if format or size causes problems. These are guide recommendations, not assurances of current product pricing or availability.
